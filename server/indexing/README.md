# Indexing

RAG 인덱싱 파이프라인. `docs/` 폴더의 PDF를 검색 가능한 벡터로 만들기까지 4단계로 이뤄져 있고,
각 단계는 독립된 스크립트입니다.

**이건 서버가 아닙니다.** `stt_service`나 `orchestrator`처럼 계속 떠 있는 프로세스가 아니라,
필요할 때(최초 1회, 또는 `docs/`에 문서가 추가·수정됐을 때) 실행하고 끝나는 배치 스크립트입니다.
`uvicorn`으로 띄우는 게 아니라 그냥 `python`으로 실행합니다. 실시간 요청을 처리하는 STT/오케스트레이터와
달리 속도보다 재실행·검증 편의성이 중요해서, 단계를 하나로 합치지 않고 이렇게 나눠서 유지합니다.

| 단계 | 스크립트 | 상태 |
|---|---|---|
| 1. 문서 로드 | `load_documents.py` | 구현됨 |
| 2. 청킹 | `chunk_documents.py` | 구현됨 |
| 3. 임베딩 | `embed_chunks.py` | 구현됨 |
| 4. Chroma 저장 | `store_chroma.py` | 구현됨 |

## 설치

```bash
pip install -r requirements.txt
```

특별히 "서버"에서 돌려야 할 이유는 없습니다 — `docs/` 폴더에 접근 가능한 아무 PC에서나 실행하면 됩니다.
지금은 이 PC(로컬)에서 실행하면 되고, 나중에 실제 배포 시에는 벡터DB(Chroma)가 올라갈 GPU 서버에서
실행하게 될 가능성이 높습니다 (3·4단계인 임베딩·저장이 그 서버에서 이어질 거라서).

## 1단계 — 문서 로드 (`load_documents.py`)

```bash
python load_documents.py
```

`docs/`의 PDF에서 텍스트를 페이지 단위로 추출해 `output/`에 PDF당 JSON 파일 1개로 저장합니다.
추출 경로는 2단계입니다:

1. **텍스트 레이어 (pypdf + PyMuPDF, 페이지별 선택)** — 디지털 PDF는 여기서 끝. 원본 그대로라
   가장 정확하고 빠릅니다. 두 추출기는 깨지는 방식이 정반대라(자간을 글자별로 배치한 표는
   pypdf가 "부서업 무총괄"처럼 공백을 끼우고, 세로쓰기 셀은 PyMuPDF가 "미/술/실"처럼 한 글자씩
   줄바꿈) 페이지마다 둘 다 뽑아 한 글자짜리 한글 조각 비율이 낮은 쪽을 씁니다. PyMuPDF의
   세로쓰기 한 글자 줄은 한 단어로 합칩니다("교무기획부"). 망미중 교육계획서 123쪽 실측:
   pypdf만 쓰면 6쪽, PyMuPDF만 쓰면 8쪽이 깨지지만 페이지별 선택이면 깨진 페이지가 0쪽입니다.
   채택한 추출기는 페이지의 `layer_engine` 필드에 남습니다.
2. **표 → 마크다운 표 (PyMuPDF `find_tables`)** — 괘선 좌표로 셀을 잡아 표를 마크다운 표로 옮기고,
   표 밖 글자는 텍스트 블록으로 읽기 순서(위→아래)대로 합칩니다. 글자는 레이어 원문 그대로이면서
   행·열 관계가 보존됩니다(학사일정표의 날짜↔행사, 교직원 현황의 항목↔숫자, 배치도의 층↔교실).
   세로 병합된 첫 열(부서명·월 등)은 아래 행에 값을 채우고, 세로쓰기 셀은 한 단어로 합칩니다.
   짧은 셀(12자 이하)의 자간 공백은 없앱니다("학 급 수" → "학급수", "구 분" → "구분").
   **학사일정표(달력형)의 행사 행**은 바로 위 날짜 행의 칸에 합칩니다 — 한 주가 날짜 행 + 행사 행
   두 줄이라 그대로 두면 "24(목)"과 "추석연휴"가 다른 행에 떨어집니다. 윗 행에 날짜 칸("24(목)",
   "10/1(목6)")이 2개 이상이고 이 행에는 없을 때만 합치므로 교과 시수표·평가 항목표 같은 세로 병합
   표는 건드리지 않습니다(09-17 실측: 조건 없이 합치면 그 표들이 뭉개졌음).
   표 버전의 글자 수가 레이어 대비 85% 미만이면(괘선을 표로 오인) 레이어를 유지합니다.
   망미중 교육계획서 실측: 123쪽 중 89쪽이 표 페이지(`extraction: "text_layer+tables"`,
   `tables` 필드에 표 개수). VLM이 필요 없고 서버·개발 PC에서 결과가 같습니다.
3. **백지 페이지 건너뜀** — 텍스트 레이어가 없고 저해상도 렌더링의 잉크 비율이 0.2% 미만이면
   장 구분용 빈 면으로 보고 VLM에 보내지 않습니다(`extraction: "blank"`, 빈 텍스트라 조각이
   생기지 않음). 빈 이미지를 받은 VLM은 "이미지를 제공받지 못했습니다" 같은 사과문을 지어내고,
   그것이 그대로 인덱싱되어 검색에 섞이는 사고가 실측으로 확인됐기 때문입니다. 백지 판정을
   통과했는데도 VLM이 사과문을 돌려주면 그것도 버리고 `vlm_empty`로 남겨 사람이 확인하게 합니다.
4. **VLM 전사 ([vlm_service](../vlm_service/))** — 다음 페이지를 PNG로 렌더링해
   비전 모델로 전사합니다. 표·레이아웃 구조를 살린 텍스트를 기대할 수 있습니다.
   - **스캔본 페이지**: 텍스트 레이어가 페이지당 20자 미만 (백지 제외)
   - **도해 페이지**(조직도 등): 3×3 이하의 작은 "상자" 표가 5개 이상인 페이지. 상자 안 글자는 표
     추출로 정확히 들어가지만 상자 사이의 관계(소속·연결선)는 텍스트에 남지 않으므로, VLM에
     관계 설명문만 받아 페이지 원문 앞에 붙입니다(`vlm+layer`). VLM이 없으면 표/레이어 텍스트만
     인덱싱하고 로그에 남깁니다. `VLM_DIAGRAM_PAGES="파일명:26"`으로 특정 페이지를 강제할 수 있습니다.
   - **깨진 텍스트 레이어**: 두 추출기 모두에서 한 글자짜리 한글 조각 비율(요일 등 원래 한 글자인
     단어 제외)이 기준(0.45) 이상인 경우 — 그대로 인덱싱하면 임베딩·검색 품질이 크게 떨어지기
     때문. 이 경우 **VLM 전사와 공백을 제거한 레이어 원문을 함께 인덱싱**합니다
     (`extraction: "vlm+layer"`) — 소형 VLM이 세로쓰기 병합 셀(부서명 등)을 놓치거나 글자를
     오독해도, 그 값들은 레이어 원문에 정확히 있으므로 어느 쪽으로 검색해도 걸립니다.
     VLM 전사가 실패하거나 잘리면 경고만 남기고 텍스트 레이어를 유지합니다.

**실행 전제**: vlm_service(기본 `http://localhost:10000`)와 그 뒤의 vLLM 서버가 떠 있어야
합니다. VLM이 준비되지 않으면 기동을 거부하고 exit 1로 끝납니다 — 스캔본 페이지가 빈
텍스트로 인덱싱되는 "조용한 실패"를 막기 위한 동작입니다. 텍스트 레이어만으로 돌려보는
개발 환경에서만 `VLM_REQUIRED=0`으로 완화할 수 있습니다.

```json
{
  "source_file": "스쿨패스 사전신청 안내문.pdf",
  "total_pages": 3,
  "extracted_chars": 4210,
  "avg_chars_per_page": 1403.3,
  "layer_engines": { "pypdf": 2, "pymupdf": 0 },
  "broken_layer_pages": [],
  "table_pages": 1,
  "diagram_pages": [],
  "blank_pages": [],
  "vlm_pages": [2],
  "vlm_empty_pages": [],
  "failed_pages": [],
  "pages": [
    { "page_number": 1, "text": "...", "extraction": "text_layer+tables", "layer_engine": "pypdf", "tables": 1 },
    { "page_number": 2, "text": "...", "extraction": "vlm", "layer_engine": "pypdf", "tables": 0 }
  ]
}
```

페이지 번호를 함께 저장해두는 이유는, 나중에 답변에 "OO 매뉴얼 3페이지 근거"처럼 출처를 밝히기
위해서입니다. `extraction` 필드는 각 페이지가 어떤 경로로 추출됐는지 남겨 운영 중 품질 추적에
씁니다 (`text_layer` / `text_layer+tables` / `vlm` / `vlm+layer` / `blank` / `vlm_empty` / `failed` / `skipped`).

스캔본 페이지의 VLM 호출이 재시도(기본 3회, 지수 백오프)를 소진하거나 **출력이 토큰
한도로 잘리면**(vlm_service의 `truncated` 응답) 해당 페이지를 `failed_pages`로 기록하고
**전체를 exit 1로 종료**합니다 — `run_all.py`가 이후 단계를 중단하므로 불완전한 인덱스가
만들어지지 않습니다. 잘림이 반복되면 vlm_service의 `VLM_MAX_TOKENS`와 vLLM의
`--max-model-len`을 상향하세요.

### 환경변수

| 변수 | 기본값 | 설명 |
|---|---|---|
| `VLM_SERVICE_URL` | `http://localhost:10000` | vlm_service 주소 |
| `INTERNAL_API_KEY` | (필수) | vlm_service와 공유하는 내부 키 (로컬 개발은 `ALLOW_DEV_KEYS=1`) |
| `VLM_REQUIRED` | `1` | `1`: VLM 미준비 시 기동 거부. `0`: 텍스트 레이어만으로 진행 (개발 전용) |
| `VLM_CACHE` / `VLM_CACHE_DIR` | `1` / `indexing/vlm_cache` | VLM 전사 결과를 `<PDF 해시>_p<쪽>_dpi<DPI>_<프롬프트 해시>.json` 으로 저장해 재인덱싱 때 재사용. PDF 내용·DPI·프롬프트가 같으면 `--with-vlm` 없이도 도해·스캔본 전사가 그대로 들어간다(조각 규칙만 바꿨을 때 20분 → 3분). 프롬프트를 고치면 키가 바뀌어 자동으로 새로 전사. 캐시를 버리려면 폴더 삭제 |
| `VLM_RENDER_DPI` | `250` | 스캔본 페이지 렌더링 해상도. 150에서는 빽빽한 표의 병합 셀 오독 사례가 있음. 서버(Qwen3-VL-8B, 32k)는 250, 3B·12k 구성이면 200 |
| `VLM_TIMEOUT` | `120` | 페이지당 VLM 호출 타임아웃(초) |
| `VLM_RETRIES` / `VLM_RETRY_BACKOFF` | `3` / `2` | 재시도 횟수 / 백오프 밑수(대기 = 밑수^시도, 초) |
| `LOW_TEXT_THRESHOLD` | `20` | 이 글자 수 미만이면 스캔본 페이지로 판단 |
| `BLANK_PAGE_INK_PCT` | `0.2` | 스캔본 후보 페이지의 잉크(어두운 픽셀) 비율이 이 값(%) 미만이면 백지로 보고 VLM에 보내지 않음. 실측: 백지 0.00%, 글자 있는 페이지 최소 5.3% |
| `BROKEN_LAYER_RATIO` | `0.45` | 한 글자짜리 한글 조각 비율(요일 등 제외)이 두 추출기 모두 이 값 이상이면 깨진 레이어로 판단해 VLM 재추출 |
| `TABLE_MODE` | `1` | `find_tables`로 표를 마크다운 표로 변환. `0`이면 레이어 텍스트만 |
| `TABLE_MIN_KEEP_RATIO` | `0.85` | 표 버전 글자 수가 레이어 대비 이 비율 미만이면 표 오인으로 보고 레이어 유지 |
| `DIAGRAM_MIN_BOXES` | `5` | 3×3 이하 작은 표가 이 개수 이상이면 도해 페이지 → `--with-vlm` 때 관계 설명 추가 |
| `VLM_DIAGRAM_PAGES` | (없음) | 도해로 강제할 페이지: `"파일명(확장자 제외):페이지"` 쉼표 구분 |

## 2단계 — 청킹 (`chunk_documents.py`)

```bash
python chunk_documents.py
```

1단계 출력(`output/*.json`)의 페이지 텍스트를 검색 단위로 잘게 나눠 `output_chunks/chunks.jsonl`에
한 줄당 조각 1개(JSON Lines)로 저장합니다. 페이지 단위로 자르기 때문에 조각마다 어느 문서 몇 페이지에서
왔는지가 그대로 유지됩니다.

- **조각 크기**: 1,200자, **겹침(overlap)**: 150자 — bge-m3(입력 8192토큰) 전환으로 상향. 표가 많은 페이지의 조각화를 줄인다
- **자르는 위치**: 1,200자 지점에서 무조건 자르지 않고, 그 앞 120자 안에서 문장부호(`.`, `!`, `?`, 줄바꿈)나
  공백을 찾아 그 지점에서 자릅니다 — 단어 중간이 끊기는 걸 방지
- **표 헤더 유지**: 마크다운 표(1단계 표 추출)가 조각 경계에 걸리면 뒷조각 앞에 헤더 행(+구분선)을
  다시 붙이고, 겹침 시작점이 표 행 중간이면 그 행의 처음으로 당깁니다 — 조각 혼자서도
  "이 숫자가 어느 열의 값인지" 알 수 있게
- **표 행 사실 조각(`kind: "fact"`)**: 페이지 조각과 별개로 마크다운 표의 **행 하나**를
  `"{표 제목} — {행 머리}: {열 이름} {값}, …"` 한 줄로 편 작은 조각을 함께 만듭니다
  (예: `학급 편제 및 학생수 — 학생수: 1 83, 2 81, 3 91, 계 255(5)`,
  `2학기 학사일정 — 9: 주 6, 21(월5), …, 24(목) 추석연휴, 25(금) 추석, 수업일수 3`).
  이유(09-17 실측): reranker(cross-encoder)는 짧고 초점 있는 지문에는 0.6~0.95 를 주지만 같은 사실이
  1,200자 표 조각에 묻히면 0.01 아래로 떨어져 무관 질문과 구분이 안 됐고, 달력·통계표·조직표 질문
  5건이 그래서 "찾을 수 없음"이었습니다. 행 조각은 **검색·재채점 전용**이며 LLM 컨텍스트는
  rag_service 의 페이지 확장(small-to-big)이 페이지 전문으로 바꿔 줍니다(`kind=fact` 는 전문에서 제외).
- **산문 조각(`prose_facts`, 역시 `kind: "fact"`)**: 표 밖 본문에서 **숫자가 든 문장 하나** 또는 **연속된 짧은 줄 묶음**
  (인포그래픽의 "자원 이용 / 최대 3개월 / 무상 제공")을 같은 방식의 짧은 조각으로 만듭니다. '값'은 숫자·영문 낱말(PPST)·따옴표 이름(‘협성회’)이고,
  마침표 없는 "라벨 값" 줄들이 한 덩어리로 붙어 160자를 넘으면 원래 줄 단위로 되돌립니다(소개자료의 "운영 특징 … 매일 7교시"). 09-18 실측(AICA 기관소개,
  표가 거의 없는 소개자료): 표 행 조각이 없어 700~1,000자 페이지 조각만 남았고 reranker 가 긴 조각에 낮은 확률을 줘
  "최대 3개월 무상", "총사업비 약 105억원" 이 검색 0건이었습니다. PDF 줄바꿈으로 잘린 문장은 이어 붙이고, 출처·각주·URL 줄과
  3쪽 이상 반복되는 머리말·꼬리말(`repeated_lines`, 숫자를 지운 형태로 비교)은 뺍니다. 망미중 123쪽 실측: 산문 조각 245개.
  값이 없어도 조각이 되는 두 경우(09-21 실측, 배재고 p8 "철인의 메스가 뭐야" 가 페이지 조각만으로는 1초 거절): **정의 줄**
  "라벨 — 설명"/"라벨: 설명"(`_PROSE_DEF`, 라벨 24자 이하 — "철인의 메스 — 철학·인문학·… 융합형 프로그램")과 **소제목 아래 문장**
  ("동아리 · 비교과 — 자율탐구프로그램과 … 활동이 활발합니다"). 산문 조각 수: 배재고 63→119, 망미중 270→325, AICA 84→104.
  긴 셀(200자 초과 또는 글머리표 항목 2개 이상)은 항목별로 쪼개고("주요 일정: 여름방학: 2026.7.22.(수)
  ~ 2026.8.17.(월) 27일간"), 헤더에 칸 하나만 찬 표(`| 교무기획부 |  |`)는 그 칸을 표 제목으로 씁니다
  (`교무기획부 — 부장: 이OO`). 망미중 123쪽 실측: 페이지 조각 약 300개 + 행 조각 약 1,800개.
  `--with-vlm` 으로 만든 **도해 페이지의 VLM 설명문**(`[페이지 원문]` 표식 앞부분)도 한 줄 = 조각 하나로
  같이 색인합니다 — 조직도의 "교장 허OO 아래에 교감 서OO가 있다" 같은 줄이 "교장 선생님 성함" 질문에 걸리게.

```json
{
  "chunk_id": "스쿨패스 사전신청 안내문_p1_c0",   // 행 조각은 _p1_f0, _p1_f1, …
  "source_file": "스쿨패스 사전신청 안내문.pdf",
  "page_number": 1,
  "chunk_index": 0,
  "kind": "page",                                // "page" 본문 조각 / "fact" 표 행 조각
  "text": "..."
}
```

실제 실행 결과(14개 문서 기준): 총 580개 조각, 평균 289자, 최소 12자, 최대 399자.

## 3단계 — 임베딩 (`embed_chunks.py`)

```bash
python embed_chunks.py
```

2단계 출력(`output_chunks/chunks.jsonl`)의 각 조각을 의미를 담은 벡터로 바꿔
`output_embeddings/embeddings.jsonl`에 (원본 조각 정보 + `embedding` 필드) 형태로 저장합니다.

- **모델**: `BAAI/bge-m3` (다국어, 568M 파라미터 — 1024차원, 입력 한도 8192토큰). 한국어 검색에서 관련/무관 질문의 거리 분리가 e5-small 대비 뚜렷하다 (실측: 갭 +0.14)
- **접두사 규칙**: bge-m3는 접두사가 필요 없습니다. (e5 계열로 되돌릴 경우 문서 `"passage: "`, 질문 `"query: "` 접두사를 복원해야 합니다)
- **정규화(normalize)**: 벡터를 단위 벡터로 정규화해서 저장 — 나중에 코사인 유사도 계산이 단순 내적(dot product)
  한 번으로 끝납니다.

```json
{
  "chunk_id": "스쿨패스 사전신청 안내문_p1_c0",
  "source_file": "스쿨패스 사전신청 안내문.pdf",
  "page_number": 1,
  "chunk_index": 0,
  "text": "...",
  "embedding": [0.0123, -0.0456, ...],
  "embedding_model": "intfloat/multilingual-e5-small",
  "embedding_dim": 384
}
```

실행이 끝나면 데모 질문("스쿨패스는 어떻게 신청하나요?")으로 실제 검색까지 자동으로 테스트해 콘솔에
상위 3개 결과를 보여줍니다 — 임베딩이 실제로 의미 검색에 쓸 만한지 매번 눈으로 확인할 수 있습니다.

실제 실행 결과(580개 조각 기준): 임베딩 계산 57초(조각당 평균 0.098초, CPU), 데모 질문 검색 결과 상위 3개
모두 "서비스 이용 신청", "사전 신청 승인" 등 실제로 관련된 매뉴얼 구절이 정확히 검색됨.

## 4단계 — Chroma 저장 (`store_chroma.py`)

```bash
python store_chroma.py
```

3단계 출력(`output_embeddings/embeddings.jsonl`)을 Chroma 벡터DB에 저장합니다. `chroma_db/`
폴더에 로컬 파일로 영속화되는 임베디드 DB라 별도 서버가 필요 없습니다. 컬렉션 이름은 `schoolpass_docs`.

- **거리 방식**: 코사인(`hnsw:space: cosine`)으로 명시 — 3단계에서 정규화해둔 벡터와 계산 방식을 맞춤
- **메타데이터**: `source_file`, `page_number`, `chunk_index`에 더해 `scope`(common/institution),
  `institution_id`를 저장. 지금 문서는 전부 범용 매뉴얼이라 `scope="common", institution_id=""`로 들어감.
  나중에 기관별 문서가 생기면 `scope="institution", institution_id="<기관ID>"`로 저장하고, 검색 시
  `where={"$or": [{"scope": "common"}, {"institution_id": 기관ID}]}`처럼 필터링하면 공통 문서와
  해당 기관 문서만 검색 대상이 됩니다.
- **재실행 안전**: 스크립트를 다시 돌리면 기존 컬렉션을 지우고 새로 만들어서, 중복 저장되지 않습니다.

실행이 끝나면 저장된 DB에서 직접 데모 질문으로 검색까지 자동 검증합니다.

실제 실행 결과(580개 조각 기준): 전부 정상 저장, 데모 질문 검색 결과가 3단계에서 직접 계산했던 코사인
유사도(0.901/0.898/0.896)와 Chroma가 반환한 거리(0.0991/0.1024/0.1038 = 1 − 유사도)가 정확히 일치 —
저장·검색 파이프라인이 처음부터 끝까지 검증됨.

## 폴더별(부분) 인덱싱 — `--only`

기관 문서 하나가 바뀌었을 때 전체를 다시 돌리지 않는다. `docs/` 바로 밑 폴더 이름(`common` 또는 기관ID)을 지정하면
그 폴더의 문서만 load→chunk→embed 하고, Chroma 에서는 **그 폴더(scope/기관)의 조각만 지우고 새로 넣는다**. 다른 기관 색인은 그대로.

```bash
python run_all.py --only 7010170            # docs/7010170/ 만
python run_all.py --only common,7010170     # 여러 폴더
bash deploy/gpu_server/05_index_documents.sh --only 7010170 --with-vlm   # 서버에서 (서비스 내리고 올리는 것까지)
```

- 각 단계는 환경변수 `INDEX_ONLY` 로 같은 값을 받는다 (run_all 이 넘겨 줌). 단계를 따로 돌릴 때는 `INDEX_ONLY=7010170 python chunk_documents.py` 처럼.
- 부분 인덱싱은 `indexing/output/<폴더>` 만 비우고 `output_chunks/`·`output_embeddings/` 는 그 폴더 결과로 덮어쓴다(전체 결과 파일이 아니다).
- 기존 컬렉션의 임베딩 모델이 다르면 거부한다 — 그때는 `--only` 없이 전체 재인덱싱.
- 컬렉션이 아예 없으면(첫 실행) 새로 만든다.
