# 개발 규칙 (DEV_RULE)

이 프로젝트(한국어 RAG 키오스크)에서 코드를 고칠 때 지키는 규칙이다.
항목마다 실제로 사고가 났던 사례를 근거로 남긴다. 위로 갈수록 중요하다.

---

## 1. 차단 검사는 측정 전에 켜지 않는다

**사고(09-29):** `verify.missing_subject`(질문 낱말이 근거에 없으면 거절)를 처음부터 차단으로 넣었다가
골든이 110/120 → 86/120 으로 떨어졌다. 목표 3건 중 1건만 고치고, 통과하던 25건을 깨뜨렸다.

- 새 검증은 **로그만 → 재생성 1회(막지 않음) → 차단** 순서로 올린다.
  - 좋은 예: `verify.missing_part`(복합 질문 항목 누락)는 재생성 1회만 하고, 나아지지 않으면 1차 답변을 그대로 내보낸다.
- 위험한 새 동작에는 환경변수 스위치를 단다.
- 측정 후 효과가 있으면 스위치를 없애고, 실패하면 **코드째 삭제**한다. 꺼 둔 채 남겨 두지 않는다.

## 2. 새 검사는 지난 골든 답변에 먼저 돌려 본다

**사고(09-29):** 손으로 고른 대조군 14개가 어미 형태(`층이야`·`시작했어`)를 하나도 안 담고 있어서 오탐을 못 봤다.

- 대조군을 손으로 고르지 않는다.
- `rag_service/golden/last_report_*.json` 에 실제 질문·답이 있다. 새 검사 함수를 여기에 돌려
  **통과했던 문항 중 몇 개를 잡는지** 센다. 모델 없이 순수 함수로 몇 초면 끝난다.
- 통과 문항을 하나라도 잡으면 그 이유를 설명할 수 있을 때까지 서버에 올리지 않는다.

## 3. 한 회차에 한 종류만 바꾼다

**사고(09-23):** rag_service 수정과 인덱싱 수정을 같은 회차에 올려, 회귀 원인 두 개를 분리하는 데 시간이 들었다.

| 바꾼 곳 | 반영 방법 |
|---|---|
| `rag_service/rag/*` | `sudo systemctl restart rag_service` |
| `indexing/*` | `--only` 로 대상 디렉토리만 재인덱싱 (끝나면 rag_service 자동 재시작) |

두 종류를 같은 회차에 섞지 않는다.

## 4. 문서 맞춤 수정 금지

- 증상 문자열을 지우는 식으로 고치지 않는다. 예: `TA L E N T D E V E LO P M E N T` 를 지우는 대신,
  원인(PDF 자간 → PyMuPDF 가 만든 가짜 공백)을 `TEXT_INHIBIT_SPACES` 로 고쳤다.
- 기관명·고유명사·특정 문서의 문자열을 코드 규칙(정규식·목록)에 넣지 않는다.
- 근거는 주석에 `실측(날짜, 문항 id)` 형식으로 남긴다 — 이 코드베이스의 관례다.
- 서식 특화 규칙은 **안 맞으면 아무것도 안 하게(fail-safe)** 만든다.
  - 좋은 예: `linearize_calendar_tables` — 달력 행이 3개 미만이면 원문 그대로.
  - 나쁜 예: `_FLOOR_HEAD` — 열 머리가 `1층 | 2층 | 3층` 인 표를 만나면 머리 행을 데이터로 바꿔 열 이름을 잃는다.

## 5. 텍스트를 지우거나 바꾸는 처리는 안전장치부터

**사고(09-23):** 각주 위첨자를 처음 일치하는 곳에서 지웠다가 `1,528명` 의 `1` 이 사라졌다.

- 지우기·바꾸기는 **대상이 유일할 때만** 한다 (예: `text.count(full) == 1` 일 때만 줄 교체).
- 결과를 검증할 수 있으면 검증한 뒤에만 채택한다.
  - 예: `TEXT_INHIBIT_SPACES` 추출은 한글 사이 공백 수가 원래와 같을 때만 받아들인다.

## 6. 한국어 낱말 대조의 함정

- **질문 낱말 ≠ 명사.** `층이야`·`시작했어`·`맡아`·`어느`·`각각` 도 낱말로 잡힌다.
- 조사·어미는 **접두 일치**로 흡수한다 (`입학식은` → `입학식`).
- 띄어쓰기 차이는 공백을 뗀 형태로도 대조한다 (`상담 교사` = `상담교사`).
- 기존 함수(`textutil.question_overlap`, `verify._line_has_token`, `textutil.whole_word_hits`)가 이미 이렇게 한다.
  새로 만들지 말고 이걸 쓴다.
- "질문 낱말이 문서에 없으면 ~" 류 판정은 형태소 분석기 없이는 하지 않는다.

## 7. 빈 입력과 경계를 확인한다

**사고(09-23):** 영문 제목 문서(common)의 제목 낱말 집합이 비어 있었고, `search_question` 이 빈 집합을 빼고
교집합을 구해 기관명을 지웠다. 배재고 문항 4개가 common 문서에 밀렸다.

- 집합 연산, 첫·마지막 원소, `max`/`min` 을 쓸 때 **빈 입력 · 영문 전용 · 원소 하나** 경우를 따로 생각한다.

## 8. 편집 도구

**사고:** bash heredoc 이 Python 문자열의 `\n` 을 실제 줄바꿈으로, `\b` 를 백스페이스(`\x08`)로 바꿨다.
`indexing/chunk_documents.py` 303행의 이상한 공백도 같은 흔적으로 보인다.

- 정규식·이스케이프가 든 Python 코드는 셸 heredoc 으로 쓰지 말고 에디터(Edit 도구)로 고친다.
- 고친 뒤 구문을 확인한다.
  ```bash
  python -c "import ast; ast.parse(open('파일.py', encoding='utf-8').read())"
  bash -n 스크립트.sh
  ```

## 9. 측정과 보고

- 3세트 × 3회로 측정한다.
  ```bash
  cd /root/ai-agent/deploy/gpu_server && bash golden_check.sh -n 3 mangmi_2026 aica_2026 paichai_2026
  ```
- 보고서는 `rag_service/golden/last_report_<세트>_<회차>.json` 으로 남는다. 다음 실행이 덮어쓰므로
  `0. golden 측정/<YYMMDD>_<n>/` 으로 복사해 보관한다.
- 이전 회차와 **문항 단위로** 비교한다. 합계만 보면 고친 것과 깨진 것이 서로 상쇄돼 안 보인다.
- 실패 원인은 보고서의 `why` 필드부터 본다.
- 서버에 올릴 때는 **바뀐 파일 목록**과 **재시작으로 충분한지 / 재인덱싱이 필요한지**를 함께 적는다.

## 10. 작업 방식

- "수정금지" 요청이면 계획만 쓴다.
- 로컬에서 모델(LLM·임베딩·리랭커)을 돌리거나 백그라운드 실행을 하지 않는다.
  검증은 서버에서 한다. 모델 없이 도는 순수 함수 검사는 괜찮다.
- 요청한 범위만 고친다. 묻지 않은 기능(예: 골든 보고서의 path 필드)을 붙이지 않는다.

## 알려진 위험 규칙 (indexing/chunk_documents.py, 2026-10 점검)

새 문서를 넣을 때 오작동할 수 있는 규칙들이다. 고치기 전까지는 새 문서 인덱싱 후 결과를 직접 확인한다.

| 규칙 | 위험 |
|---|---|
| `_DATE_SPLIT` | `YYYY.MM.DD.` 만 자른다. `2021.11`, `2024`, `2021년 3월` 은 놓친다 (a38 원인 후보) |
| `_FLOOR_HEAD` | 열 머리가 층인 배치도에서 열 이름을 잃는다 |
| `survey_target` | `%` 하나로도 설문 라벨이 다음 쪽에 이어져, 예산·통계 쪽에 "설문 결과" 문구가 잘못 붙는다 |
| `_merge_loose_rows` | 사례 1건(AICA p8)에서 만든 규칙. 2열 표 뒤 짧은 줄 2개가 본문인데도 표 행으로 흡수될 수 있다 |
| 표 안 1~2자 줄 무시 | `합계`·`비고` 같은 2자 줄이 제목으로도 안 잡히고 표도 안 끊긴다 |

과적합 여부는 지금 골든(3개 문서)으로는 측정할 수 없다. **처음 보는 문서**(다른 학교 교육계획서 1개 + 학교가 아닌 문서 1개)로
골든 세트를 추가해야 측정할 수 있다.
