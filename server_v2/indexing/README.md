# 인덱싱 단계 분리

이번 회차는 `snapshot.py`로 기존 인덱스를 일관된 상태에서 복사해 새 RAG에 연결한다.
새로운 문서 추출·청킹은 아직 실행하지 않는다. 원문 PDF와 모델 가중치는 복제하지 않는다.
snapshot.py는 switch.sh가 기존 서비스를 중지한 뒤 호출한다.

다음 인덱싱 회차의 계약:

- 문서 내용 해시와 추출/청킹 버전으로 인덱스 revision을 만든다.
- 원문, 정규화 텍스트, 페이지/표/행/열/셀 위치와 변환 이력을 JSON으로 보존한다.
- Chroma는 검색 텍스트와 연결 키를 저장하며 중첩 표 관계는 외부 JSON에 둔다.
- 파싱 불가/병합 셀 모호함은 명시하고, 추측으로 표 값을 채우지 않는다.
- 새 인덱스 생성 → 일관성 검사 → 서비스 중지 → 인덱스 버전 전환 → 기동 순으로 반영한다.

기존 인덱스 snapshot.json과 chroma_db는 한 묶음으로 보관한다. 기존 스냅샷을 자동 덮어쓰지 않는다.
